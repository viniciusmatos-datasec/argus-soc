# Guia de Contribuição e Padrão de Commits

Para manter o histórico do repositório limpo e rastreável, este projeto utiliza o padrão **Conventional Commits**. 

## Estrutura da Mensagem
O commit deve seguir o formato: `<tipo>: <descrição curta>`

## Tipos Permitidos
* **feat**: Adição de uma nova funcionalidade (ex: novo script de coleta de logs).
* **fix**: Correção de um bug (ex: erro na formatação dos dados).
* **docs**: Mudanças apenas na documentação (ex: atualização do README).
* **chore**: Atualizações de tarefas de manutenção ou setup (ex: criação de pastas).
* **refactor**: Alteração de código que não corrige bugs nem adiciona features.
* **test**: Adição ou correção de testes automatizados (ex: pytest).

## Exemplos
* `feat: cria notebook de transformacao de dados`
* `docs: atualiza arquitetura da fase 1`
* `chore: adiciona arquivo gitignore`
